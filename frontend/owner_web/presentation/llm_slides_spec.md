# Spec: Генерация HTML-слайдов презентации «Контекст»

## Общее описание задачи

Ты - дизайнер презентаций. Твоя задача - сгенерировать HTML-файлы для каждого слайда презентации проекта «Контекст» для конкурса стартап-проектов РГЭУ (РИНХ).

Каждый слайд - это **отдельный HTML-файл**, который можно открыть в браузере и сделать скриншот / распечатать / конвертировать в PDF.

---

## Технические требования

### Размер и формат слайда

- Каждый HTML-файл - один слайд.
- Размер слайда: **1920×1080px** (16:9, Full HD).
- Слайд должен быть обёрнут в контейнер с фиксированными размерами:

```html
<div class="slide" style="width: 1920px; height: 1080px; overflow: hidden; position: relative;">
  <!-- содержимое слайда -->
</div>
```

- Никакого скролла - всё содержимое должно помещаться в рамки слайда.
- Шрифты подключаются через Google Fonts (Inter, Montserrat или другие sans-serif).

### Стиль и цветовая палитра

**Палитра «Контекст» (корпоративная, технологичная, доверительная):**

| Роль          | Цвет      | HEX       |
|---------------|-----------|-----------|
| Primary       | Тёмно-синий (navy) | `#1A2332` |
| Secondary     | Синий (accent) | `#2B6CB0` |
| Accent        | Бирюзовый | `#38B2AC` |
| Background    | Светло-серый | `#F7FAFC` |
| Surface       | Белый     | `#FFFFFF`  |
| Text Primary  | Тёмный    | `#1A202C`  |
| Text Secondary| Серый     | `#718096`  |
| Success       | Зелёный   | `#48BB78`  |
| Warning       | Оранжевый | `#ED8936`  |

**Типографика:**

| Элемент          | Шрифт       | Размер   | Вес  |
|------------------|-------------|----------|------|
| Заголовок слайда | Montserrat  | 48–56px  | 700  |
| Подзаголовок     | Montserrat  | 28–32px  | 600  |
| Основной текст   | Inter       | 20–24px  | 400  |
| Акцентный текст  | Inter       | 24–28px  | 600  |
| Подпись/caption  | Inter       | 16–18px  | 400  |

**Отступы и spacing:**

- Padding от краёв слайда: минимум 80px.
- Между блоками контента: 40–60px.
- Между заголовком и контентом: 48px.

**Общие правила дизайна:**

- Минимализм. Много воздуха. Не перегружать текстом.
- Каждый слайд должен содержать визуальный элемент (иконку, диаграмму, блок с акцентом, цветную плашку) - не только текст.
- Иконки: использовать SVG-иконки (можно inline SVG или Lucide/Heroicons через CDN).
- Для списков: не стандартные буллеты, а кастомные (иконки, цветные точки, нумерация в круглых плашках).
- Акцентные цифры/метрики - крупным шрифтом (60–80px), с подписью мелким.
- Таблицы - стилизованные, с чередованием строк, без тяжёлых бордеров.
- Никаких подчёркиваний под заголовками (это маркер AI-генерации).

## Структура слайдов (8 штук)

**Layout:** Тёмный фон (`#1A2332`). По центру - название проекта крупно. Ниже - подзаголовок. В нижней части - «Стартап как диплом в РГЭУ (РИНХ)».

**Контент:**

- Название: **Контекст**

- Внизу: Стартап как диплом в РГЭУ (РИНХ)
- Визуальный элемент: абстрактная геометрия или лёгкий паттерн из связанных узлов (символизирует граф знаний) - можно реализовать через CSS/SVG.

### Слайд 2 - Проблема (`slide_02_problem.html`)

**Layout:** Светлый фон. Заголовок слева вверху. Два блока проблем - карточки с иконками.

**Контент:**

- Заголовок: **Проблема**
- Карточка 1 (иконка: поиск/лупа):
  - **Документация превращается в хаос**
  - Сотрудники тратят до 1,8 часа в день на поиск информации. Документы дублируются, устаревают, теряются.
- Карточка 2 (иконка: щит/замок):
  - **Данные нельзя хранить в чужом облаке**
  - Банки, госсектор, крупный бизнес обязаны хранить данные на собственных серверах. Российские аналоги не дотягивают по функционалу.
- Акцентная метрика справа или по центру внизу: **9,3 ч/нед** - тратит средний сотрудник на поиск информации (McKinsey).

### Слайд 3 - Решение и УТП (`slide_03_solution.html`)

**Layout:** Светлый фон. Заголовок. Три колонки с ключевыми технологиями - карточки или иконка + текст.

**Контент:**

- Заголовок: **Наше решение**
- Подзаголовок: Единственная российская вики с AI-поиском, работающая полностью on-premise
- Три колонки:
  1. Иконка (мозг/нейросеть): **Семантический поиск** - поиск по смыслу через NLP и эмбеддинги, а не по ключевым словам.
  2. Иконка (слои/стопка): **Слоёная архитектура** - контроль зависимостей между документами по принципу FSD. Порядок вместо хаоса.
  3. Иконка (чат-бот): **RAG-ассистент** - AI-помощник отвечает на вопросы по базе знаний со ссылками на источники.
- Внизу: плашка с текстом: «Все данные остаются на серверах компании»

## Проверка качества (QA)

После генерации каждого слайда проверь:

1. **Помещается ли всё в 1920×1080?** Никакого overflow.
2. **Читается ли текст?** Достаточный контраст, размер шрифта ≥ 20px для основного текста.
3. **Есть ли визуальный элемент?** Каждый слайд - не просто текст.
4. **Консистентность:** Одинаковые отступы, шрифты, цвета на всех слайдах.
5. **Нет ли подчёркиваний под заголовками?** (запрещено - маркер AI).
6. **Не перегружен ли слайд?** Лучше убрать текст, чем впихнуть лишнее.
