## Decisions

### Сверка с меню после отказа

Goden в отказе называет продукты, а не блюда. Какие блюда заказа не проходят, Мигом узнаёт из меню точки (`GET /points/{pointId}/menu`): Goden гарантирует, что число порций в меню совпадает с решением заказа. Меню читается только после отказа, поэтому обычный заказ не получает лишнего запроса. Блюдо заказа, которого нет в меню (снято с продажи, в архиве), считается отсутствующим.

Меню читает delivery_service своей функцией `goden.menu()`, как business_service: общего пакета у сервисов нет (вывод из кода).

### Текст ответа

Ответ остаётся 409 с текстом в `detail`: приложение показывает `detail` как есть (`ApiException`), отдельные поля ему не нужны. Формат: `Пока вы оформляли заказ, изменилось наличие: Маргарита - нет в наличии; Паста - можно не больше 1. Измените корзину` (допущение по формулировке).

### Окно отмены

На главном экране, где уже слушается `order.status_updated` (окно подтверждения доставки), при статусе `cancelled` приложение читает заказ и показывает окно, только если есть `cancel_reason`: отмену без причины делает сам покупатель или Мигом.

## Risks / Trade-offs

- Наличие могло измениться между отказом и чтением меню: тогда список может не совпасть с отказом; покупатель повторит заказ и получит актуальный ответ.
- Недоступность Goden при чтении меню - прежний текст с продуктами, без новой ошибки.
