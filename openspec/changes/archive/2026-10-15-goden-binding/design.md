## Context

API Goden принимает токен пользователя Мигома (`aud` `goden-api`) с правами этого пользователя: владелец компании Goden читает свой профиль (`GET /me`), подключает Мигом к своей точке (`PUT /points/{pointId}/migom`, тело `{outlet_id}`) и читает меню точки (`GET /points/{pointId}/menu`).

## Decisions

- **Запросы в Goden - с токеном пользователя из запроса.** business_service передаёт в Goden тот же access token, с которым пришёл владелец. Права проверяет Goden: точку чужой компании подключить нельзя. Сервисная учётная запись `migom-integration` здесь не нужна, она понадобится для заказов.
- **Сначала Goden, потом база Мигома.** При подключении Мигом вызывает Goden и только после успеха сохраняет `goden_point_id`. Если сохранение не удалось, повтор с той же точкой безопасен: повторная запись того же номера в Goden ничего не меняет. При смене точки старая точка отключается в Goden после подключения новой.
- **Отключение не блокируется отказом Goden.** Если Goden отвечает 403 или 404 (пользователь больше не владелец, точку отключили), связь в Мигоме всё равно снимается: Мигом не будет обращаться к этой точке. Недоступность Goden (сеть, 5xx) - ошибка 503, ничего не меняется.
- **Уникальность - ограничениями базы.** Частичные уникальные индексы на `outlets.goden_point_id` и `(company_id, goden_dish_id)` у товаров; нарушение - 409 с понятным текстом.
- **Связь по названию** сравнивает названия без учёта регистра и пробелов по краям и связывает только однозначные пары: блюдо без связанного товара и ровно один несвязанный товар компании с таким названием.

## Risks / Trade-offs

- Любой токен Мигома действует в API Goden с правами пользователя. Прав сверх своих он не даёт; это принято вместо обмена токенов.
- Если владелец точки потеряет права в Goden, связь в Мигоме останется до отключения. Следующий change сверяет пару с `GET /migom/points` при обращениях к Goden.
