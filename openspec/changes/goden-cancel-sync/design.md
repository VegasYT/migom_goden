## Decisions

### Опрос, а не webhook или Kafka

Выбор пользователя. Опрос не требует новой операции в Goden и общей сети двух стендов, а пропущенная отмена дойдёт следующим проходом. Альтернативы: webhook из Goden (очередь повторов и подпись на стороне Goden), чтение Kafka Goden (внутренний формат событий Goden становится контрактом). Задержка до 15 с для отмены допустима.

### Фоновая задача в delivery_service

`app/core/goden_cancel_worker.py` по образцу `offer_worker.py` (вывод из кода): задача asyncio из `lifespan`, проход раз в 15 с, ошибка прохода пишется в журнал и не останавливает задачу. Проход выбирает заказы с `goden_order_id`, кроме `delivered`, `received`, `cancelled`, и для каждого читает `GET /points/{pointId}/orders/{orderId}` новой функцией `goden.order()`. Заказов в работе немного, запрос на заказ проще, чем фильтр отмен по времени в Goden.

Ошибки чтения: недоступность Goden (`GodenUnavailableError`) прерывает проход, следующий повторит; 403 и 404 (заведение отключили, точку выключили) пропускают заказ.

### Отмена в Мигоме

Отдельный метод `OrderService.cancel_from_goden`: перечитывает заказ, повторно проверяет статус (заведение могло отменить его в тот же момент), ставит `cancelled` с причиной, сбрасывает активный заказ курьера и публикует `order.status_updated`, как `owner_cancel`, но без `_return_to_goden`. Повтор безопасен: отменённый заказ проход больше не выбирает.

`order_status_history.changed_by` обязателен и хранит ID пользователя Мигома. У отмены из Goden пользователя Мигома нет: пишется 0 (допущение, сервисного пользователя в Мигоме нет).

### Причина отмены

Столбец `orders.cancel_reason` (nullable, миграция Alembic) и поле `cancel_reason` в `OrderResponse`. Комментарий берётся из `cancel_comment` заказа Goden.

## Risks / Trade-offs

- Goden без правки `order-cancel-by-staff` не отдаёт `cancel_comment`: причина будет "Отменён рестораном".
- Сотрудник Goden может отменить заказ, который кухня уже готовит: Goden вернёт продукты на склад. Это решение сотрудника Goden, Мигом только отражает отмену.
- Несколько экземпляров delivery_service опрашивали бы одни заказы; повторная проверка статуса в `cancel_from_goden` не даёт отменить дважды, лишним будет только запрос. Сейчас экземпляр один.
