# Business Service

Сервис управления бизнес-сущностями платформы Migom (агрегатор доставки еды).

## Зона ответственности

- Регистрация и вход пользователей через Keycloak Goden (realm `goden`): токены выдаёт Keycloak, роль и блокировка - в базе Мигома
- Управление компаниями и каталогом товаров, фото в MinIO
- Торговые точки компаний, расписание работы, наличие товаров
- Отзывы покупателей, скидки, промокоды, промо-баннеры
- Уведомления пользователей
- Связь заведений с точками Goden и товаров с блюдами Goden: запросы в API Goden (`GODEN_API_URL`) идут с токеном пользователя, права проверяет Goden

## Стек

- **FastAPI** + **SQLAlchemy async** (asyncpg)
- **PostgreSQL 17** с поддержкой PostGIS
- **Redis** - кэш меню и списка компаний (TTL 5 мин)
- **MinIO** - хранение фото позиций меню и аватаров пользователей

## Архитектура

Модульная структура: каждый модуль содержит `router`, `service`, `repository`, `schemas`, `exceptions`.

```
app/
├── modules/
│   ├── auth/          # Регистрация, login, logout, refresh токена
│   ├── users/         # Профиль, аватар, смена пароля, блокировка
│   ├── companies/     # CRUD компаний, блокировка
│   ├── catalog/       # Глобальные категории и позиции меню, фото
│   ├── outlets/       # Торговые точки, наличие товаров, менеджеры
│   ├── reviews/       # Отзывы покупателей
│   ├── discounts/     # Скидки и промокоды
│   ├── promo/         # Промо-баннеры
│   └── notifications/ # Уведомления пользователей
├── core/              # проверка токенов, клиенты Keycloak и API Goden, зависимости, кэш, хранилище
└── db/                # Сессия, базовая модель
```

## Запуск

Сервис запускается через Docker Compose из папки `infra/`:

```bash
docker compose up -d
```

Swagger UI: [http://localhost/business/docs](http://localhost/business/docs)

## Миграции

```bash
docker exec migom_business_service alembic upgrade head
```

## Роли

| Роль | Описание |
|---|---|
| `customer` | Покупатель - заказы, корзина, адреса, способы оплаты |
| `owner` | Владелец компании - управляет своими компаниями и меню |
| `courier` | Курьер - управляется через delivery_service |
| `outlet_manager` | Менеджер торговой точки, добавляется владельцем по email |
| `moderator` | Полный доступ ко всем сущностям, назначается вручную через БД |

### Goden

Владелец Мигома и владелец точки Goden - один пользователь общего Keycloak: Мигом обращается в API Goden с его токеном (у токенов `migom-backend` есть `aud` `goden-api`). Если Goden недоступен, ответ 503 и данные Мигома не меняются.

| Метод | URL | Доступ | Описание |
|---|---|---|---|
| `GET` | `/goden/points` | Авторизованный | Работающие точки Goden, которыми владеет пользователь, и подключённые к ним заведения |
| `PUT` | `/outlets/{id}/goden` | Владелец / moderator | Подключить заведение к своей точке Goden (`{"point_id": "<uuid>"}`) или отключить (`null`); точка - не больше чем у одного заведения |
| `GET` | `/outlets/{id}/goden/dishes` | Владелец / moderator | Блюда точки Goden подключённого заведения и связанные товары |
| `POST` | `/outlets/{id}/goden/link-by-name` | Владелец / moderator | Связать блюда без товара с единственным несвязанным товаром того же названия |

Товар связывается с блюдом полем `goden_dish_id` при создании и изменении (`POST`/`PATCH /companies/{id}/items`), `null` снимает связь; блюдо - не больше чем у одного товара компании.

Меню подключённого заведения (`GET /outlets/{id}/menu`) показывает только товары, связанные с блюдами, которые на точке Goden можно приготовить, и не выключенные вручную; кеш 20 секунд. Наличие читает сервисная учётная запись `migom-integration` (`GODEN_CLIENT_ID`, `GODEN_CLIENT_SECRET`) после сверки пары "точка - заведение" с `GET /migom/points`: если Goden не подтверждает пару, меню пустое. Если Goden недоступен, связанные товары показываются по ручной доступности.
